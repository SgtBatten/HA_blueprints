# Frigate Notifications 0.14.0.4 beta 1

This beta adds configurable GenAI update stages, native Matrix media delivery, and independent camera cooldowns. Install through the repository's **BETA** blueprint import link. Back up existing automation inputs before upgrading.

## GenAI and phone notifications

- Late Sprinters are suppressed for every object ID in a qualifying Final review. Retained MQTT markers require no additional helpers; they protect for 24 hours, with hourly cleanup of up to 100 expired markers. Checks before phone and Matrix delivery also cover runs delayed by media downloads.
- Separate Sprinter object-description and Final review-summary controls, including description and attachment choices for each stage.
- Final summaries prefer `shortSummary`, with fallbacks for other summary payload formats and an explicit nonempty-result check.
- Optional cleanup of secondary object Sprinter notification tags when a final review summary arrives, using the configured Tag template.
- Ordinary review updates exclude GenAI MQTT messages, avoiding competing text updates from the ordinary review loop.
- Camera matching falls back to the selected entity's object ID when its Frigate camera-name attribute is unavailable.
- Custom filters are evaluated after event variables and refreshed during ordinary updates.
- Cooldown calculations use elapsed timestamps, and MPEG-4 attachment hints use the iOS-compatible `mpeg4` value.
- Single-device clip links are adjusted for Android/iOS, and a separate iOS update interruption-level setting is available.
- Thirty stored traces and up to fifty parallel runs support multi-camera troubleshooting.

## Notification services and Matrix

- Select an existing `notify.*` action as an additional destination while retaining phone delivery.
- Choose service stages independently: **Frigate Initial**, **Frigate Final**, **GenAI Sprinter**, and **GenAI Final**. Service GenAI selections work independently of phone GenAI toggles.
- Native Matrix mode uploads the selected image/GIF, then sends a combined **bold title, description, and View clip link**.
- Blank Matrix titles receive a camera-based fallback; titles and descriptions are escaped for HTML.
- Matrix room IDs/aliases, media cache directories, and Downloader subdirectories are configurable.
- Download completion/failure events gate media upload, with diagnostic logging and text fallback for failed downloads.
- Generic service mode sends text and media/clip links. Matrix receives new room messages rather than phone-style tag replacements.
- Notify All Devices remains available alongside device/group targeting.

## Independent camera cooldowns

- **Minimum Sprinter Interval per Camera** limits admitted Sprinter runs across object IDs on the same camera, for both phone and service delivery. A value of `0` disables it.
- **Regular Notification Cooldown Scope** offers per-camera initial-notification cooldowns alongside legacy automation-wide behavior.
- Per-camera regular cooldowns keep review-update workers active and do not block end updates or GenAI Final summaries.
- Each enabled cooldown uses its own Timer helper per camera; regular and Sprinter timers are separate. Missing helpers produce explicit diagnostics instead of unlimited sends.

## Setup and compatibility

- Home Assistant baseline: **2024.11**. Native `nfandroidtv.send_message` delivery requires **2026.11+**.
- Frigate baseline: **0.14**, with Frigate review GenAI support and configuration required for Final summaries; review summaries require a compatible Frigate 0.17+ release.
- Existing upstream Telegram bot selection, plain-text caption handling, and Android/Fire TV notify-entity delivery are included.
- Sprinter updates default off; the existing beta's Final GenAI behavior remains enabled by default. Both new timer-based limits require deliberate configuration.
- Matrix inline media requires Downloader, a writable cache directory, and that directory in `homeassistant.allowlist_external_dirs`. A relative subdirectory supports shared Downloader roots and private caches.
- See [Beta Setup](../Beta%20Setup.md) and [Timer helper examples](../examples/CooldownTimers.example.yaml).

## Beta notes and validation

The built-in Matrix integration emits a text event during image upload. The preview-first path uses empty text, which some clients display as an empty bubble. GIF animation depends on the client. Concurrent runs can interleave room events.

Timer cooldowns are practical gates, not atomic quotas: simultaneous parallel runs can race. Throttled Sprinter descriptions are dropped, not queued. Phone notification cleanup follows Companion App platform limits. Cache retention is managed separately; downloaded files are not automatically purged.

Ten automated checks pass for YAML/input integrity, template parsing and helper calls, summary validation/fallbacks, Matrix formatting/media payloads, service-stage controls, separate timer paths, and upstream Telegram/TV compatibility. Additional targeted checks cover the cooldown gates and preview/caption sequencing. Trace-based testing confirmed phone final-summary actions, per-camera Sprinter suppression, Matrix text and image/GIF delivery. The regular per-camera cooldown and the preserved platform combinations still need broader beta testing.

Concurrent-event validation confirmed three Final phone/Matrix send sequences, independent camera cooldowns, six-object finalization, and two late Sprinters blocked after Final commitment. These traces confirm send actions, not handset receipt. Hourly marker cleanup has automated coverage but still needs live beta validation. The guard commits before Final delivery; if delivery fails, matching Sprinters remain suppressed during the protection window.
